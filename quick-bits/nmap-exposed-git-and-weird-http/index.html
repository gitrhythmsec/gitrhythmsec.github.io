My Nmap Scan Found More Than Open Ports

Status: InformationalNovember 6, 2026

What I Saw

I scanned one of my development Raspberry Pis for fun. Nmap found SSH, a Python website-preview server on TCP 1337, and a Vite development server on TCP 5173. Later, the Python server's logs looked like somebody was throwing random web requests and binary garbage at it.

Investigation

I compared the server logs against my own scan time and source machine. They contained requests for nonexistent paths, unsupported HTTP methods such as PROPFIND, and TLS handshake bytes sent to a plain HTTP service. One request was especially definitive:

GET /nmaplowercheck... HTTP/1.1  404

Nmap's service detection was probing how the server responded. Its http-git script also found an accessible .git directory. Requests to /.git/config and related metadata returned HTTP 200, allowing Nmap to identify the repository's remote and latest commit message.

What It Turned Out to Be

My own authorized Nmap scan, not an unexpected visitor. The .git exposure was real, though. The repository was for a public website, but serving Git internals directly isn't a practice I want to repeat with private code.

Why It Mattered

Recognizing scanner fingerprints kept me from mistaking routine testing for an incident. It also gave me a concrete web-server configuration issue to clean up: serve a separate preview directory without .git.
