The SMB Connection to My Old University

Status: InvestigatingOctober 22–31, 2026

What I Saw

My connection-monitoring dashboard showed a Windows workstation repeatedly trying TCP 445 (SMB) toward an unfamiliar public address. That's not a connection I expect a gaming laptop to make to the internet, so I investigated rather than dismissing it.

Investigation

I inspected archived Suricata flows and found repeated attempts on different days involving TCP 445, TCP 80, and UDP 443 toward the same remote endpoint. The captured flows showed outbound packets, zero return packets observed, and timeouts. That didn't establish that any SMB session or authentication succeeded.

A network ownership lookup associated the destination with a university I had attended. The address suddenly looked familiar. I remembered using that university's network, confirmed the old Wi-Fi profile was saved, and found a Credential Manager target matching the exact destination. Checks for current SMB mappings and obvious persistent Explorer network locations came back empty.

What It Turned Out to Be

A known historical destination, but not a fully explained connection. The saved credential strongly linked the computer to that remote address; it did not prove which program initiated the recent requests.

Why It Mattered

The suspicious-looking connection became much less mysterious once I correlated network logs with old endpoint configuration. I still wouldn't mark its initiating process as identified without endpoint evidence.
