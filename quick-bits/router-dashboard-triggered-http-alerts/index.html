When My Router Dashboard Triggered Suricata

Status: BenignOctober 2026

What I Saw

Suricata kept generating SURICATA HTTP Request unrecognized authorization method (SID 2221034, Priority 3) alerts for traffic from my Windows workstation to my router's web interface. An authentication-related alert aimed at the router deserved a closer look.

Investigation

I checked the HTTP request context with the IDS logs and packet capture. The requests used a Firefox User-Agent and targeted router administration API paths. I had the router's management page open in Firefox.

I closed that tab and the alerts stopped. Opening it again produced another burst of roughly two dozen alerts; closing it stopped them again.

What It Turned Out to Be

Normal router administration traffic matching Suricata's HTTP parser rule. The repeated open/close test tied the alerts to the management tab rather than an unknown process or attacker.

Why It Mattered

This was a useful little controlled experiment. Instead of guessing from the rule name, I changed one thing—whether the admin page was open—and watched the alert behavior follow it.
